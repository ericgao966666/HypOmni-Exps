**先写结论。** 用几句话交代问题、最关键的结果（含基线和差值）、证据范围与主要限制。尚无结果就明确写“待验证”，不要填入启动成功、检查通过或运行次数。

## 研究问题与关键设置

假设是什么？与什么比较？哪项观察能支持或推翻假设？

| 影响结果解读的设置 | 本轮口径 |
|---|---|
| 数据与划分 | 数据版本、样本量、排除规则、训练/验证/测试隔离 |
| 方法与对照 | 改变什么、哪些条件保持一致、初始化差异 |
| 训练预算与种子 | 各条件实际预算；不足或不匹配必须说明 |
| 选择规则 | checkpoint/参数依据什么验证指标，测试前是否锁定 |
| 指标与判定 | 方向、聚合、单位、评分函数、成功门槛 |

正文写明影响解读的配置，完整配置和来源用本地路径及哈希定位；已发布的研究协议可使用 Markdown 链接，不逐条展开运行字段。

## 主要结果

给出能够支持开头结论的 Markdown 比较表，包含基线、改进条件和负结果。说明validation/test、样本数和checkpoint口径；无结果不编造表格。

各可比较指标列按方向与显示精度标记**最优**和<ins>次优</ins>；并列同样标记。缺失与零值分开，种子数/轮数等配置字段不排名。

图件仅保存在本地。正文说明图所支持的发现、数据、采样范围与模型条件，用代码格式标注本地路径，不嵌入 GitHub 无法显示的图片。降维图不能单独证明包含关系，需原空间诊断或投影质量。汇总性的完整方向对比表可另链到 Markdown 报告；逐轮/逐样本明细留在本地，关键结果仍留在正文。

## 解释与局限

分别说明：观察到了什么；可能的原因；什么仍未证实。明确预算、数据、初始化、选模、缺失条件及单种子限制。测试后改预算或改选择规则等事件不能藏进运行日志。
